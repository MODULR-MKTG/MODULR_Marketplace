# /mine-subscriber-language

Turn free-text from polls and surveys into a structured audience-language file. Always cites the source. Never paraphrases away from the subscriber's actual words.

## Before you start

1. **The beehiiv MCP must be connected.** If not, stop and tell the user.
2. Confirm the publication.

## Configure the mine

Ask via AskUserQuestion only if not specified:

1. **Window** — last 90 days / 6 months / 12 months / all time (default 12 months)
2. **Source** — polls only / surveys only / both (default both)
3. **Minimum response length** — 5 words / 10 words / 20 words (default 10 — filters out "yes" / "no" / "ok" noise)

## Pull the data

1. `mcp__beehiiv__list_polls` — all polls in the window. Page through.
2. For each poll: `mcp__beehiiv__get_poll` for question text, then `mcp__beehiiv__list_poll_responses` for the responses. Page through. Keep only free-text responses (skip multi-choice — pure multi-choice doesn't reveal vocabulary).
3. `mcp__beehiiv__list_surveys` — same flow with `mcp__beehiiv__get_survey` and `mcp__beehiiv__list_survey_responses`.
4. Filter to responses ≥ the minimum length.
5. Keep a stable anonymized ID for each respondent (e.g. `s/{hash-of-subscriber-id}` — never the email).

## Theme the responses

Bucket each response into one or more of these five categories. Quote ranges should be exact — never paraphrase.

### 1. Fears

What keeps them up at night. Look for: "I'm worried that…", "I struggle with…", "I'm afraid…", "I can't…", "I keep failing at…", anxiety markers.

### 2. Desires

What they want. Look for: "I want to…", "I wish I could…", "if I could just…", "my dream is…", outcomes framed as goals.

### 3. Objections

What stops them from buying / acting. Look for: "I tried but…", "it didn't work because…", "I can't afford…", "I don't have time…", reasons-not-to.

### 4. Outcomes described

How they describe success or transformation in their own words. Look for past-tense wins, before/after framing, "now I can…", "I finally…", "what changed was…".

### 5. Words they use vs. words they reject

Vocabulary patterns:
- **Use:** words and phrases that recur across multiple respondents
- **Reject:** words from the user's `voice-os/context/anti-ai-phrases.md` (if present) that show up in responses (rare — but if subscribers themselves use generic-marketing phrasing, that's data); plus words/phrases respondents explicitly push back on ("don't call it X, it's actually Y")

## Write the audience-language file

Write `voice-os/context/audience-language.md`:

```
# Subscriber language — {publication} — last updated {YYYY-MM-DD}

Source: {N} free-text responses across {N} polls and {N} surveys, last {window}.

## Fears (in their words)

> "I'm scared I'll send this and nobody will read it." — s/a8f3
> Source: "Biggest blocker right now?" (poll, 2025-04-12)

> "I'm exhausted from trying every framework. Nothing sticks." — s/c2d1
> Source: "What's holding you back?" (survey, 2025-02-03)

[...8-15 quotes total. Pick the most representative, not the most extreme.]

### Synthesis

{2-3 sentences naming the dominant fear pattern. Use their words.}

## Desires (in their words)

[Same structure — 8-15 quotes + synthesis.]

## Objections (in their words)

[Same structure.]

## Outcomes described (in their words)

[Same structure. These are gold for proof-point language and testimonial framing.]

## Vocabulary

### Words and phrases that recur
- "{phrase}" — {N} respondents
- "{phrase}" — {N} respondents
- ...

### Words and phrases respondents reject
- "{phrase they pushed back on}" — context: "{the actual response}"
- ...

## Notes for drafting

- Use these phrases verbatim when possible. Subscribers wrote them.
- Lead with the fear they named most often. It's the unblocker.
- The outcomes section is the citation library for "what changes when this works" — but only quote with permission (check `voice-os/context/offers.md` for consent rules if set).

## Provenance

Generated by /mine-subscriber-language on {date}.
Sample: {N} responses ({N} polls, {N} surveys).
Window: last {window}.
```

## Also write the raw report

Write `voice-os/outputs/subscriber-language-{YYYY-MM-DD}.md`:

- Full list of every response that made it past the length filter
- Stable IDs so the user can trace any quote back
- Counts per category
- Skipped responses with reason (too short / non-English / etc.)

{deltas}

If the user says yes, update `voice-os/context/audience.md` directly. If pick-which, show a per-item selector.

If `voice-os/context/audience.md` doesn't exist, tell the user: "Run `/setup-voice-os` from `modulr-voice-os` to seed your audience file, then re-run me. Or I can write a starter audience.md from these findings — want me to?"

## Hard rules

- **Quote exactly.** Never paraphrase to make a response sound sharper. The subscriber's exact words are the point.
- **Anonymize.** Use a stable hash ID — never paste an email address or full name into the output file.
- **Cite the source.** Every quote names its poll/survey and date.
- **Skip multi-choice-only.** Multi-choice tells you what they picked, not how they think. Free-text is the source of vocabulary.
- **Don't invent themes.** If only one respondent named a particular fear, don't elevate it to a "dominant pattern." Be honest about sample size.
- **Don't pitch MODULR consulting.** That's `consulting-info`'s job (from `modulr-voice-os`).
